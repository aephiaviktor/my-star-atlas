How to read this page

Experiment summary

Daily rates: SDU / day and Net ATLAS / day are 24-hour equivalents based on active experimental time.

Shows the selected scanning experiment, its available analyzable scan-result records, and the experiment-level economics derived from those rows.

Formula: Selected experiment rows, optionally limited to Optimization data, grouped by the experiment ID and selected start date.

Interpretation: Use this as the data-quality check before trusting the charts. Runtime progress can be higher than analyzable rows when older scan results were not stored in telemetry.

Value distribution

Shows individual scan outcomes for each tested parameter value; the larger marker is the group mean.

Formula: Each scan result is plotted by selected chart metric, grouped by the active optimization parameter value.

Interpretation: Look for separation between group means, but also check the spread. A lucky cluster can make a weak setting look better than it is.

Sector clusters

Maps the scanned sectors and colors them by the tested parameter value.

Formula: Scan-result rows are placed by sector coordinates and grouped by the same parameter buckets used in the ranking.

Interpretation: Use this to spot location bias. If one parameter mostly ran in a better sector cluster, compare results cautiously.

Block ranking

Ranks tested optimization blocks by the selected table parameter and exposes the main scan, value, time, movement, and net ATLAS metrics.

Formula: Rows are grouped into contiguous experiment blocks by parameter and value, then metrics are aggregated per block.

Interpretation: The best block is the strongest candidate setting, but prefer settings with enough scans and reasonable elapsed time over tiny samples.

How to read this page

Faction LP redemption vs player LP per upgrading crew

Each dot is one completed UTC day comparing total faction redemption with this player’s LP per average hourly phantom crew.

Formula: Player LP per crew = daily player LP / average hourly phantom crew; correlation compares that value with faction LP redeemed that day.

Interpretation: Higher correlation means the player’s upgrading pace moves with the faction’s redemption pattern; it is directional evidence, not proof by itself.

ATLAS / LP vs LP / average crew

Each dot is one completed UTC day comparing the exact on-chain ATLAS value of one LP with this player’s LP produced per average phantom crew.

Formula: LP / average crew = daily player LP / 24-hour time-weighted average phantom crew.

Interpretation: This is the price-neutral production response: it shows whether automation changes production intensity as LP becomes more or less valuable.

ATLAS / LP vs component cost / average crew

Shows daily component consumption valued in ATLAS against the exact redemption value of one LP.

Formula: Component cost / average crew = daily installed component cost / 24-hour time-weighted average phantom crew.

Interpretation: Higher spending at higher ATLAS/LP can indicate the automation is using components when production is more valuable; days with incomplete prices are omitted.

ATLAS / LP vs actual − neutral baseline uplift / average crew

Compares the actual plan against the complete neutral planned baseline for the same day and plots the economic difference per average phantom crew.

Formula: Uplift = (actual LP − neutral LP) × ATLAS/LP − (actual component cost − neutral component cost); uplift / average crew = uplift / 24-hour time-weighted average phantom crew.

Interpretation: The zero line is the reference: positive values mean actual automation beat neutral at that day’s redemption rate. Transaction costs are excluded because a neutral counterfactual transaction cost is not directly observed.

Expected Total LP by EOD vs actual

Each line follows one day’s hourly forecast. The final dot is the actual faction LP redemption.

Formula: Hourly expected_total_lp_eod snapshots are plotted against the final daily faction LP redemption.

Interpretation: Distance from the line to the final dot is forecast error at that hour; tighter lines mean the forecast stabilized earlier in the day.

Forecast error by snapshot hour

Shows the signed forecast error distribution for each snapshot hour.

Formula: Error = expected total LP by EOD - actual faction LP redemption; the line is median error and the band is the middle 50%.

Interpretation: Above zero means overestimation; below zero means underestimation. A narrow band means that hour is more reliable.

Component profit margin vs faction LP redemption

Shows how each component’s implied redemption value compares with its current GM price or its internal cost across 10B–50B faction LP redemption, according to the LP Analysis cost-basis toggle.

Formula: Margin = (((faction ATLAS pool / faction LP redemption) × component LP) / selected component cost - 1) × 100.

Interpretation: Above zero means redemption value exceeds the selected cost; below zero means the selected cost is higher. The faction-colored line marks yesterday’s redemption.

Component Efficiency Frontier

Compares component return and earning speed at yesterday’s faction LP redemption. Bubble size represents cargo weight; crossed-out points are Pareto-dominated. Use the legend to include or exclude components; INK starts excluded so it does not compress the other points. The unified basis toggle controls the prices used by this chart.

Formula: X = profit margin; Y = net ATLAS/s; gross ATLAS/s = LP/s × faction ATLAS pool / faction LP; net ATLAS/s subtracts the selected component price / upgrade duration.

Interpretation: Points farther right and higher are stronger. The drawn line connects the non-dominated points on the two visible axes.

LP Analysis yesterday

Use one unified price basis across the table, Component Net ATLAS, Component Profit Margin, and Component Efficiency Frontier. External uses current GM prices. Internal uses complete production-chain costs from Breakeven Analysis. Equal Net keeps the best External component fixed and calculates the price each other component needs to match its Net ATLAS/s. Custom uses saved profile/faction/component overrides and otherwise inherits live External prices.

Formula: Breakeven LP = faction ATLAS pool × component LP / selected price. LP/s = component LP / upgrade duration. Gross ATLAS/s uses yesterday’s faction LP; all downstream profitability metrics use the selected price.

Capital-limited: Profit Margin measures percentage return on the selected component price.

Crew-limited: Net ATLAS/s measures absolute earning speed after the selected component price.

Cargo-limited: Net ATLAS/cargo unit = (implied redemption value − selected component price) / cargo weight.
